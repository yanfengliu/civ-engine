The primary adversaries are:

| Area | Independent cases and observation required |
| --- | --- |
| Lazy acquisition | Construct a public iterator without starting it: no selected-file descriptor/read. Pre-start return/throw must not acquire one. First next opens once. Missing selected file yields empty; a non-ENOENT open error preserves existing identity. An ENOENT-like error after successful open is not automatically a missing-file exemption. |
| Actual horizon | A literal short LF-terminated first record followed by more than one block of records: first next requests/consumes at most the one 65,536-byte block, with no hidden readFileSync of that JSONL. Several subsequent records already in that block must yield without another read. Leading empty LF lines, boundary-ending LF, and a first line longer than one block establish the precise bound. A final unterminated record requires actual EOF knowledge; a zero-byte EOF read is not additional consumed data. |
| Yield ordering | Valid first record followed by malformed completed text in the same block: first next returns the valid record; only the later next throws. A consumer stopping after the valid record must not trigger parsing of the suffix. Exercise the five actual public stream methods so an eager outer wrapper cannot hide behind a correct helper. |
| Physical tail | `broken\nbroken` must throw on the completed first line. `{"tick":1}\nbroken\nbroken` first yields its prefix, then throws. A malformed completed final line throws even at file EOF; only malformed final unterminated text is ignored. Valid unterminated JSON values yield. Empty string/LF-empty lines are skipped; whitespace-only completed lines, including an empty CRLF line's `\r`, must not silently acquire new trim-based semantics. Ordinary JSON followed by CRLF remains parseable. |
| UTF-8 compatibility | Compare literals with the legacy whole-buffer UTF-8 interpretation, without deriving the oracle from the candidate decoder. Place 2/3/4-byte characters at every block split. Include a split UTF-8 BOM, a BOM at file start and inside a JSON string, isolated continuation bytes, overlong/invalid leads, interrupted sequences, and incomplete final sequences flushed at EOF. Replacement characters inside strings may be valid JSON; malformed bytes outside strings and a BOM before JSON must retain the legacy parse/tail treatment. A pending sequence followed by physical LF must not lose that line boundary. |
| Value compatibility | Literal objects, arrays, strings, numbers, booleans and null remain JSON values; do not introduce record-shape filtering in the internal reader. Empty/missing streams and writer/MemorySink/loading equivalence remain covered by existing tests. |
| Ownership and precedence | Exhaustion, early public return, public injected throw, read failure and parse failure close the owned descriptor exactly once. After a yielded value, inject `undefined`, `null`, `false`, `0` and `''`, each with close also throwing, and check exact caught identity using a separate caught flag. A truthiness sentinel is insufficient. Cover native Error/object identity too. Close-only failure remains visible after normal exhaustion/return. Test public wrappers as well as any helper because generator delegation and IteratorClose can alter which exception reaches which finally block. |

Important controls are whole-file eager reading, parse-ahead within a read block, content-equality tail classification, omitted finally-close, and a cleanup-error masking primary failure. Each material control needs an actual failing case with the intended failure signal, followed by exact byte restoration and a passing native run. Assertions should use literal public outcomes, descriptor/read observations and caught identities rather than importing the implementation's own buffer constant or private predicate as their oracle. A test proving only final record count cannot establish first-yield horizon or deferred error timing.

The implementation review will trace every public stream to the helper, decoder flush/line cursor state, physical EOF classification, and all descriptor exit paths. A single fixed byte buffer does not imply constant space for an arbitrarily long record. Partial-line accumulation and JSON.parse retain the largest-record bound. No cancellation, immutable live-file snapshot or universal concurrent-modification guarantee is inferred. A descriptor that remains open while a caller abandons a started iterator without closing it is not automatically a finally defect; supported consumption/return/throw paths must be explicit.

The separately released heavy proof must record actual Node/version/platform string-limit data, a real owned JSONL file exceeding that process's aggregate string bound, independent expected bytes/record count, eager-control failure at the real boundary, candidate iteration without aggregate retention, actual native results, costs and finally cleanup. A mocked limit, small file, merely calling next once, or counting a constructed array is insufficient. This reviewer will inspect owner evidence and will not duplicate the heavy run or claim a speed/memory improvement without its measurement. Runtime and token/compute costs are presently unknown; only inspection work is being performed.
