## Reports

### Independent native Astra/xhigh source and measurement review

**Conclusion.** No material finding in the exact target. The implementation preserves the supported validation and observation contract while deferring diagnostic-path string construction. The retained evidence supports the narrow claim that five measured pairs of the actual saved-component payload used 8,095 versus 7,095 process CPU milliseconds, a 12.3533% reduction, with equal fingerprints. It does not establish a World.step, FPS, whole-game, state-fingerprint or game-memory gain. The documentation generally makes those limits explicit, and the ordinary full gate remains outstanding.

**Path construction and rejection behavior.** At `src/json.ts:12`, the new per-call array holds object keys as strings and array indexes as numbers. Lines 14–19 reconstruct the original label followed by the same dot/bracket segments only when rejecting a value. Numeric-looking object keys remain dot keys; punctuation and empty labels keep the previous spelling rather than gaining a new escaping policy. Every rejection still constructs `EngineError('json_incompatible', message, {details:{context:path}})` with the same reason text and path. Primitive acceptance, finite-number rejection, undefined/bigint/function/symbol rejection, prototype restrictions and cycle rejection remain in their original traversal positions. No new depth, size, plain-object, number or serialization policy is introduced.

**Object and array observation ordering.** The object branch at `src/json.ts:51` still gets the prototype before `Object.entries`; line 56 still evaluates that complete entries array before visiting its children. Therefore an enumerable later getter still runs before rejection of an invalid earlier child, and a getter's own exception still propagates unchanged. The array branch at line 41 still tests length in each loop iteration and reads the current index only when that iteration is visited. Sparse holes still read as undefined and fail at the same first index. Adding the private breadcrumb immediately before visiting does not read another payload property or catch a payload exception. No finally cleanup is needed for the private path/seen state on an exception: the entire invocation unwinds and its local state is discarded, while reentrant independent calls allocate their own state.

**Cycles, shared references and serialization.** The WeakSet remains an active-ancestry set: add on entry, reject an already active object, delete after successful array/object traversal. A shared acyclic object is still expanded and accepted at every sibling site; it is not mistaken for a cycle or skipped by a permanent visited cache. Breadcrumb pop after each successful child prevents sibling-path leakage. Null-prototype objects, ignored symbols/non-enumerable properties and array semantics remain governed by the same primitives as before. `jsonFingerprint` at line 67 and `cloneJsonValue` at line 78 still validate first and use the same JSON stringify/parse operations. There is no clone, fingerprint cache or retained payload registry added.

**Unchanged surrounding callers preserve the safety boundary.** I inspected `src/component-store.ts:29`, line 45 and line 57: semantic comparisons and ordinary writes still call the existing fingerprint/validation functions before their normal publication behavior. I also inspected `src/world-tick.ts:271` and line 280: baseline establishment and later comparison still fingerprint state, including the existing path for observing in-place state changes. The candidate does not skip these walks, suppress diffs, trust caller writes, change component generations or introduce an opt-out. The exact diff confirms these files, the public barrel/surface fixture and work83 occupancy implementation are unchanged. This is why the optimization is a patch, not an additive API or persistence change.

**Size and allocation tradeoffs are bounded rather than removed.** The validator still walks each accepted value completely, using the same recursion, WeakSet and Object.entries allocations. Each traversed child now adds a push/pop pair to a reusable per-invocation breadcrumb array. Its active entries occupy O(nesting depth); it does not retain previous siblings or data after the invocation. On a rejection, path reconstruction traverses those breadcrumbs and allocates the diagnostic string, and error construction still runs. The small per-call array and per-child operations can cost something on tiny values; neither the source nor the evidence justifies claiming all inputs become faster. Very deep structures still face the existing recursive stack limits. `src/json.ts` is 100 lines and the focused contract test is 92 lines, with no file-size exception or policy change.
