## Design judgment

**The proposal is suitable for a concrete R8 owner decision authorizing a bounded experiment. No material contract contradiction was found. It is not implementation, adoption or shipment approval.** The first consumer selection should remain exactly `aoe2.lastSeenStatic`, with every other key and the engine default on current observation. The owner must knowingly approve the loss of automatic in-place change detection and tick-scan validation/getter effects for selected keys. A new persistent policy field is not intrinsically necessary for the explicitly factory-restored model described here.

The proposal correctly avoids claiming that data size proves CPU cost. The independent saved-key check supports its narrower point: a primitive-only top-level shortcut touches one numeric slot, while the actual composite state remains traversed. The author's compact-byte census is useful for choosing a candidate, not a measurement of retained heap, dirty frequency, validator visits or obtainable speedup. Neither this review nor the proposal proves that a default-preserving internal optimization cannot help; that remains a separate possible bounded experiment.

There is no request to repair or rewrite the sealed proposal and no new review round is required for the two nonblocking proof clarifications below. Root can include them in the concrete decision/implementation plan before execution.

## Why the engine contract is coherent

Outside the proposal, engine `src/world-tick.ts:271-277` clears setter/removal bookkeeping and fingerprints every state value at tick start. `:280-297` seeds changes from explicit dirty keys and fingerprints only the other keys during diff construction. The proposal accurately distinguishes those phases: an explicitly dirty slot already avoids the second fingerprint. `src/json.ts:67-69` validates and then stringifies. Consequently the proposed selected-key skip is a real semantic opt-in, not an invisible cache optimization.

The existing temporal counterexamples remain valid for all default/unselected keys. Reusing an endpoint fingerprint would miss an in-tick1→0 return after a between-tick0→1 change, and would invent an in-tick change when the between-tick0→1 value remains unchanged during the tick. Equal/same-reference setter intent, deletion/reinsertion ordering and supported getter/error behavior also cannot be replaced by endpoint equality. Proposal lines172-176 preserve these defaults and explicitly retain tick-start clearing rather than introducing a new between-tick publication queue.

`src/world-observers.ts:223-234` validates setter inputs but stores/returns live references; `:244-252` implements deletion bookkeeping. Selected mode keeps those APIs and their current identity behavior. It therefore cannot claim enforced immutability or detection of every unannounced write. The proposal says so directly. `src/world.ts:115-119` still validates and clones values for full serialization. Selected keys can skip the two automatic tick scans while retaining setter/full-serialize checks; hidden mutation into invalid data need not fail at the same tick phase under the selected contract. Default keys must retain their existing error paths and observations. Removing selected getters' effects can affect an application that relied on those effects; such an application is outside the promised stable-publication discipline, not proof of equivalent semantics.

A separate runtime-options argument is the right boundary for the proposed shape. It should not be placed in serialized WorldConfig or smuggled into state/metadata/registration fields. Exact-string selection copied into an instance-owned immutable set, including absent keys and keys later deleted/reinserted, makes the policy stable without a live toggle. The final public names, invalid-option behavior and type exports still need normal API design/tests/minor-version documentation after authorization; those mechanics do not require changing the proposed owner decision.

## Restore, replay and factory obligations

The restore paragraph is materially more precise than a promise that saves simply remember the mode. Proposal line178 intentionally distinguishes a new unconfigured deserialize from restoring data into an existing configured instance. That choice is implementable against current source and must remain explicit in the owner's decision:

| Boundary | Required policy outcome |
| --- | --- |
| New World without selection | Current live-reference fingerprint observation for every key. |
| New World with copied selection | Selected keys use setter/removal observation; all others remain current mode. |
| `World.deserialize(snapshot)` without runtime options | Current mode, regardless of which mode produced the ordinary JSON snapshot. |
| Configured deserialize/factory | Selection established during construction, before stepping/recorder connection. |
| `configuredWorld.applySnapshot(snapshot)` | Receiver's immutable selection survives; only state/dirty/baseline data is replaced. |
| Game live/load/replay/seek/fork factories | Same fixed selected-key declaration where the experiment is enabled; no policy field recovered from snapshot bytes. |

Current engine `src/world.ts:169-204` has an existing deserialize runtime-options position but constructs a fresh World from config alone. `applySnapshot` at `:349-360` currently deserializes a temporary fresh world, then transfers state. `_replaceStateFrom` at `:374-386` documents preserved registration-bearing fields and at `:426-430` transfers state/dirty/removal/baseline data. A new policy field must be deliberately classified as preserved runtime registration, not copied from that temporary default world. `applySnapshot` must not become a backdoor for changing the immutable selection. The proof should cover configured receivers with present, absent and deleted selected keys plus legacy snapshot shapes.

The concrete AoE2 convergence point exists: `src/game/simulation/bridge/createWorld.ts:109-116` chooses between `World.deserialize` and `new World`; both branches need the same fixed runtime selection. `src/game/simulation/replay/createReplayWorldOnly.ts:15-31` reconstructs through that function in replay mode, so an independently maintained replay policy list is unnecessary. `src/game/replay/ReplayController.ts:92` defaults to that replay factory, and `:273-275` steps and resets the accessor. Custom factory overrides and engine fork/seek factory callers still need explicit proof; the existing factory/registration checks do not know this new policy. The proposal acknowledges that limitation rather than claiming the registration manifest guarantees it.

For conforming ordinary data and complete setter publications, using an unconfigured generic reader should retain equivalent state/diff behavior while paying the old observation cost. For a source that violates the selected contract, default and selected modes may differ; an ordinary JSON snapshot cannot certify the original policy or caller discipline. If the owner requires arbitrary readers to reconstruct the policy itself, this proposal is insufficient by design and a separate persistent-format decision is needed. Do not broaden the approved runtime-only route to satisfy that different requirement silently.

## The first game slot is a credible candidate

The important ownership evidence is present on both sides of the cache. `bridgeStateAccessor.ts:65-74` clones stored JSON before decoding the native cache. `:159-166` serializes and clones native state before setState. The map-of-map codec at `bridgeStateSerialize.ts:87-97` is shallow by itself, so retaining both surrounding clones is essential. Native Map mutations cannot reach the stored JSON through that normal path. Conversely, a forgotten native dirty mark is already a publication bug in default mode: scanning the detached stored value cannot detect a change that was never flushed.

The source census is consistent with the proposal's boundaries. `fogMemoryOps.ts:78-90` distinguishes ordinary inner-map reads from first-map creation and explicit change notification. `systems/fogMemorySystem.ts:61-91` compares complete remembered appearance/generation fields and installs fresh entries; its four deletion branches set the common changed flag, and `:258` publishes that fact once. This evidence justifies selecting one known slot for a controlled experiment, not removing clone/flush discipline or selecting every state key. ## Proof clarifications and proportionality

**C0 — make the missed-publication mutation's oracle independent.** Proposal line192 already requires an actual missing-markDirty/publication mutation to fail. Preserve that requirement concretely: use a one-sided mutant against the unmodified publication path or a literal expected fog-memory appearance/removal/full-state assertion. Applying the same lost-publication mutation to both arms can leave both stored JSON states stale and still equal; replaying the same defective source can also be self-consistent. Because the accessor clones both ways, raw selfCheck alone is not a sufficient oracle for this particular omission. This is a clarification of how to satisfy the stated test obligation, not a new contract or evidence that the present writer is defective. Include independent read-clone/write-clone removal controls so accidental aliasing cannot make default scanning conceal a missing publication.

**C1 — freeze the experiment's acceptance arithmetic and limits before launch.** The proposed5% whole-step median CPU improvement on both late inputs, above observed A/A noise and with a consistent sign, is a reasonable usefulness threshold for accepting a new caller obligation. It is deliberately a shipment/usefulness gate, not a claim that5% is statistically established by three samples. Define the A/A noise statistic, paired-ratio aggregation, valid-run counts, permitted warmup/exclusions and timeout/memory/artifact/attempt ceilings before reading the new results. At least three alternating pairs is a floor; do not add rounds until a preferred sign appears. Exceeding the resource bound should stop the bounded experiment and leave an explicit incomplete/negative disposition, not lower the proof bar.

The proof breadth is proportionate to an observation contract that affects persistence/replay despite adding no format field. Default/selected mixed worlds, both between-tick counterexamples, getter/error phases, strict setter validation, equal writes, deletion/reinsertion, applySnapshot, actual factories and missed publication are the essential correctness obligations. Full unfiltered state/diff/events/execution/economy/non-timing comparisons, recorder timing boundaries, raw selfCheck and seek/fold/fork are justified for the first adopted slot. These can be separate bounded correctness jobs rather than repeated inside every timed pair. The proposal appropriately keeps parity instrumentation and call counters outside timing and requires uninjected profiling.

The timing comparison must isolate policy: default versus selected on the same candidate artifact, plus candidate-default versus shipped2.13 to expose disabled-feature overhead. Report inclusive state-phase cost, total CPU/wall, allocation/GC and retained/RSS observations separately; shared ancestry must not be assigned to the feature or summed with nested JSON work. The5% write-heavy/default regression bound is an acceptance decision to predeclare, not permission to alter default semantics. Any behavior mismatch remains a correctness failure regardless of its cost. The plan's requirement for meaningful gains on both late inputs avoids rescuing a new obligation with a synthetic-only win, while an idle/write-heavy case guards the intended best and adverse paths.
