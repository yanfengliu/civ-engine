F0, P2 — Reject non-number maxCost values before callbacks. At src/grid-distance-field.ts:74-76, the guard uses Number.isNaN(maxCost) and maxCost < 0 without checking its type. A JavaScript caller can pass maxCost: 'bad'; Number.isNaN('bad') is false and the ordered comparison with zero is false. Later distance > maxCost comparisons are also false, so a nonempty field is computed without a bound and passability/cost callbacks run. Numeric strings, booleans and coercible objects also bypass the promised number validation. A minimal source-derived example is gridDistanceField([{ x: 0, y: 0 }], { width: 2, height: 1, maxCost: 'bad', blocked: () => { calls++; return false; } }) in JavaScript: instead of the documented pre-callback error, the code visits both cells and produces the unbounded unit-cost field. This was not executed during review.

The violation is against docs/api-reference.md:3339, which promises invalid maxCost fails before callbacks, and the work87 plan's nonnegative-number-or-Infinity contract. TypeScript annotations do not protect JavaScript callers of the exported function. Reject a non-number after resolving the existing default, before comparisons or callbacks. Add whole-class tests for nonnumeric and numeric-looking strings, booleans, arrays/objects, boxed numbers and other non-number primitives as appropriate; assert distance_field_cost_invalid and zero occupancy, blocked and cost calls. Retain numeric zero, finite bounds, Infinity, omitted/default behavior, negative numbers and NaN controls. Do not broaden this into changes to the existing findGridPath validation contract. Root acknowledged F0 during the review and committed to obtaining literal contract RED before the repair once the execution lane is available; no repair is part of this frozen target.

F1, P3 — Include the destination input count in public complexity bounds. docs/api-reference.md:3339 currently gives default work as O(cells + edges) and weighted/diagonal work as O((cells + edges) log cells). However, src/grid-distance-field.ts:78 maps every original destination into a separate seeds array, and lines106/132 scan that array again. Duplicate destinations may greatly outnumber grid cells; a one-cell grid with S duplicate inputs still takes O(S) validation/seeding work and O(S) temporary seed storage. Document S explicitly: default O(S + V + E), weighted O(S + (V + E) log V), with O(S) seed storage in addition to dense results and search scratch. The existing 12-bytes-per-cell result-array statement is correct and should remain. This is a minor wording correction, not a request to redesign storage or claim measured memory savings.

Algorithm review: the weighted branch evaluates cost(predecessor, reachedCell) at src/grid-distance-field.ts:153, retaining the forward direction of travel from the queried cell to a destination. Blocked predecessors and diagonal corner cells are excluded before cost evaluation. Negative/nonfinite edges and overflowing sums are excluded; inclusive maxCost pruning leaves out-of-range cells at Infinity/-1. No iteration budget can return an unlabeled partial result. Fresh endpoint objects prevent the cost callback from receiving references to the input destination objects.

The heap orders distance, source index and row-major cell index. Stale entries compare both distance and source. A strictly lower distance or an equal distance with an earlier source triggers propagation; zero-cost cycles therefore cannot keep improving an unchanged label. The direct tie and zero-cycle cases exercise the behavior that would be missed by distance-only testing. In the unit-cost branch, initial seeds enter FIFO order by original input index and each BFS layer preserves that ordering; first discovery therefore preserves the earliest source among equal-hop destinations. Blocked and duplicate seeds are skipped without renumbering the surviving original indices. No path or graph-canonical suffix guarantee is introduced.

Geometry/lifecycle review: dimensions are resolved using the same explicit-dimension/occupancy fallback vocabulary as the existing path helper, then checked as safe positive integers. Area and source-index limits are checked before dense allocations; these are representation limits, not allocation guarantees. Every supplied destination is validated before passability/cost calls. Empty input returns fresh unreachable arrays. The complete nonempty-grid passability snapshot combines occupancy and custom blocking with short-circuit OR, forwarding movingEntity and the default reservation policy.
