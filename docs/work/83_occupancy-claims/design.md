# Placement-only occupancy contract

## Public contract

Add OccupancyBindingOccupyOptions extending OccupancyBindingClaimOptions with blocksMovement?: boolean, and use it only for occupy(). Omission means true on each call, including a repeat of an earlier passable claim. block() and reserve() retain the existing metadata-only options. The metadata kind never selects movement behavior. OccupancyCellClaim gains optional blocksMovement; output emits only literal false on opt-in occupied claims, so every old/default output shape remains unchanged.

A passable whole-cell claim remains in raw OccupancyGrid ownership. Other entities cannot occupy or reserve its cells, and block() still refuses them. The binding filters only that occupied claim when answering movement and when its subcell grid asks whether a cell is blocked. Reservations remain separate and always use their existing default blocking behavior. includeReservations:false ignores reservations only; ignoreEntity continues ignoring the querying entity's own claims. A passable occupant must not hide that same owner's reservation from a different querying entity.

getCellStatus().blockedBy remains the complete whole-cell placement ledger. A false-tagged entry does not by itself make status.blocked true; static blockers, included reservations, solid occupied claims or full subcell capacity still do. crowdedBy/slot offsets and freeSubcellSlots retain existing meanings. Existing custom crowding predicates remain vetoes on subcell allocation; this change does not expand their existing influence on the binding's other query methods.

## Mutation and lifecycle

A passable occupy request may succeed beneath other subcell units; preserve their placements and metadata exactly. An entity converting its own subcell to a footprint loses its own old subcell/reservation as ordinary occupy already does. Solid requests continue refusing other crowded units. A passable-to-solid policy transition therefore fails atomically if another unit remains beneath it; solid-to-passable and passable moves can admit existing units.

Normalize/validate requested area, metadata and movement policy before raw claim mutation. Conflict returns false with old whole-cell, reservation, subcell, metadata, policy and binding version intact. Successful moves replace the old footprint, clear only the owner's old reservation/subcell as before, and publish one binding-version increment if cells, metadata, policy or owned lifecycle state changed. Identical normalized area, metadata and policy is idempotent. Equivalent rectangle/list, repeated and reordered cell inputs are equivalent.

Empty metadata is currently validated after underlying mutation in occupy/reserve/occupySubcell. Preflight it before committing all three methods. Area/position validation occurs first; metadata then policy (where relevant), then claim/slot conflict checks. Consequently empty metadata combined with a conflicting target throws instead of the earlier false/null result. This intentional unsupported-invalid-input precedence correction is documented; no broad promise of unchanged invalid-input error ordering is made. Existing valid inputs and other selector validation retain their behavior. A supplied nonboolean blocksMovement is rejected before mutations; omission remains true.

release(), attached-world destruction and successful conversion away from whole-cell occupancy remove movement policy. clearReservation() removes only reservation state. Detach/reattach and entity-ID reuse must not leave stale passability. No new persistence state is added: OccupancyBinding remains a runtime composition and raw OccupancyGridState is unchanged.

## Boundaries and release

Private helper composition owns policy filtering and normalized metadata preflight; OccupancyGrid's exclusive placement maps and persisted state remain untouched. Movement obstruction uses local static/occupied/reservation identities plus the private policy: never recurse through getCellStatus/free-slot queries from the subcell blocker, and never materialize getState per cell. When no placement-only claims exist, movement and subcell obstruction delegate directly to the raw grid without identity lookups, claim arrays or scans. Preserve valid-default query-counter behavior where possible; all counters must describe actual calls, and invalid metadata prevalidation may avoid scans that previously occurred before failure.
