# Visibility contract and measurement design

## Compatibility and public surface

Use the existing inclusive circle equation at integer cell coordinates: (cellX-source.x)^2+(cellY-source.y)^2<=radius^2. Accept finite fractional x/y in setSource and fromState, with0<=x<width and0<=y<height. Source finite checks precede bounds, then radius validation. Nonfinite centers use visibility_source_coords_invalid; finite out-of-bounds centers retain visibility_out_of_bounds. Radius remains finite/nonnegative. Query coordinates retain current integer validation and error timing, including unknown-player queries returning false without creating players or evaluating coordinates. No snapping, radius adjustment or cell-center offset.

State fields stay identical. Old integer states/outputs remain compatible; new fractional states require the new engine and are rejected by old integer-only readers. Engine version is the existing compatibility marker. Preserve duplicate-player merge, duplicate-source last-write, preexisting explored cells and extra own source fields retained by fromState's spread. New writes still copy documented x/y/radius as today. The owner explicitly approved this persisted-value expansion; the frozen proposal remains historical bytes.

Export VisibilityMapWorkMetrics and add getWorkMetrics(): VisibilityMapWorkMetrics, returning a detached value without flushing. Its cumulative counters are sourceRasterizations (actual source-circle enumerations), rasterizedCells (candidate integer cells whose squared distance is tested), coverageCellUpdates (actual coverage increments/decrements), serializationSorts (actual nontrivial Array.sort calls for canonical player/source/explored ordering) and serializationMergeCells (elements visited merging pending explored indices into cached ascending output). Exclude returned-state copies, query cell-array sorting, allocations and wall time; these counters are not a universal cost. Existing getMetrics shape and recomputes/computedCells/visibilityQueries semantics remain exact. resetMetrics resets both counter sets without flushing, discarding derived state or invalidating caches.

## Initial implementation boundary

Compose private coverage/order/validation helpers, leaving the public class and import paths stable and every source file below500 lines. Keep sources authoritative and separate last-applied geometry/cells from pending identities. At flush, compare final current values with applied values: decrement removed/changed applied cells, rasterize only changed/new final sources, increment coverage, and maintain visible membership where counts remain positive. Use safe sparse numbers, not a wrapping typed-array count. After the full batch, union only final visible cells into explored; retain new explored IDs for lazy ordered merge.

Existing batching is binding: insert/remove before flush explores nothing; move/revert explores no intermediate circle. A dirty batch ending at applied values still increments old recomputes and computedCells once, even with zero rasterization. Every currently flushing read continues flushing all dirty players. clearPlayer discards all derived/pending state; remove/reinsert/owner reassignment, reset while dirty and load followed by further operations must preserve exact results. Keep work79's cached normalized player/source ID order; movement reads current values without sorting IDs. All public arrays/tuples/positions/documented source fields remain detached.

## Dense-motion decision boundary

The first correctness candidate uses sparse coverage counts. It is not presumed faster when most sources move. Measure actual unit layers before accepting it. If the count-update path regresses, the concrete fallback to evaluate is a private rebuild mode chosen from changed-source fraction/work: full-motion batches use the existing direct visible-union raster path and can discard the coverage index; a later sparse batch with a cold index rebuilds that index once from final sources, then sparse batches use deltas again. The initial flush builds a warm index so the named277+2 fixture's first postwarm batch still touches only2circles.

This fallback is a proposal, not yet selected or implemented. Root must accept an evidence-derived deterministic threshold and explicit tests before it lands. Full/dense/cold-to-sparse rebuilds may rasterize all final sources and must report those actual counts; only warm sparse batches promise changed-source rasterization. Tests must pin both branch outputs, threshold transitions, no transient exploration and old metrics, and measure worst-case alternating sparse/dense transitions. If this tradeoff cannot preserve supported performance, revise the representation instead of hiding the regression or weakening the named sparse bound. No hidden source/map cap or public game-selected strategy.

Retained memory is O(sum of cached source coverage+visible cells+explored cells+source identities), with extra arrays/counts only when retained by the selected algorithm. Measure forced-GC retained heap and maxRSS separately; do not claim constant memory, peak memory from a heap delta, or zero CPU from timer quantization.
